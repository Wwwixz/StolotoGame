# СтолоПлей — быстрые игровые комнаты (MVP)

Демо-прототип веб-приложения «Быстрые игровые комнаты на бонусные баллы» для VIP-аудитории «Столото». Пользователь задаёт параметры подбора игровой комнаты, система подбирает подходящую комнату, резервирует бонусные баллы, запускает короткий раунд в одной из трёх игровых оболочек с заполнением мест ботами и определяет победителя.

## Стек

- **React 18 + TypeScript**
- **Vite** — сборка и dev-сервер
- **React Router 6** — навигация
- **lucide-react** — иконки
- **Inter** (Google Fonts) — типографика

## Запуск

```bash
cd frontend
npm install
npm run dev
```

Приложение откроется на http://localhost:5173

Продакшн-сборка: `npm run build`, предпросмотр: `npm run preview`.

## Роли

На главной странице (`/`) выбирается роль — выбор запоминается в `localStorage` и определяет доступный раздел меню. Сменить роль можно в любой момент ссылкой «Сменить роль» внизу сайдбара.

- **Пользователь** — список комнат, автоподбор, игровой цикл, история, баланс, профиль
- **Администратор** — конфигуратор комнат, анализ экономики, журнал раундов (экраны `/admin`, `/economy`, `/log` защищены: при роли пользователя редирект в лобби)

## Игровые оболочки

У комнаты есть **тип визуальной оболочки** — она лишь транслирует результат, определённый логикой раунда (пользователь не управляет исходом):

| Формат | Комната | Механика оболочки |
| --- | --- | --- |
| Колесо Фортуны | Классическая, VIP | Сектор на каждого участника; колесо останавливается на победителе |
| Гонка | Быстрая | Участники бегут к финишу; победитель финиширует первым |
| Карточный дуэль | Премиум | Каждый открывает свою карту — лучшая забирает главный приз |

Формат виден в карточке комнаты, фильтруется на `/games`, задаётся в автоподборе и в конфигураторе. После раунда победителю начисляется **бонусная сущность — выигрышная комбинация** (5 чисел), которую видно на экранах розыгрыша и победителей.

## Экономика внутри прототипа

Операции с бонусными баллами выполняются логически корректно и видны в реальном времени:

- **Вход в комнату** — баллы резервируются (доступно → резерв), сделка появляется в истории операций
- **Выход из комнаты** — резерв возвращается на доступный баланс
- **Буст** — покупается за баллы перед стартом, один на раунд, увеличивает вес игрока при выборе победителя (по умолчанию +25%); отмена возвращает баллы
- **Итог раунда** — резерв списывается; при победе игрока начисляется приз, при победе бота его часть фонда остаётся в системном фонде; история игр и журнал раундов пополняются
- **Недостаточно баллов** — вход или буст корректно запрещаются с понятной причиной и предложением подобрать комнату под баланс

Вероятность победы считается из параметров комнаты: базовая `1 / мест`, с бустом — рост веса игрока на `boostPercent` (`(1+b) / (мест − 1 + 1 + b)`).

## Параметры игры (для организаторов)

Настраиваются в конфигураторе (`/admin`) и влияют на механику:

- **Количество мест** — размер комнаты (макс. 10), базовая вероятность победы игрока = `1 / количество мест`
- **Цена входа (баллы)** — сколько бонусных баллов резервируется при входе в комнату
- **Процент фонда** — доля входов, идущая в призовой фонд; остаток — доля системы
- **Тип визуальной оболочки** — колесо / гонка / карточный дуэль
- **Буст** — покупается за баллы перед стартом раунда, один на раунд, увеличивает вес игрока при выборе победителя (по умолчанию +25%)
- Конфигуратор выводит живые предупреждения о рискованных настройках (мало мест, высокая цена, невыгодный % фонда) и показывает вероятности с/без буста

## Демо-сценарии

1. **Игровой цикл**: Лобби → «Играть» → карточка комнаты → «Войти в комнату» (резерв баллов) → ожидание (таймер) → заполнение ботами → розыгрыш в оболочке комнаты → победители → «Ещё раз в этой комнате» / «Похожие условия» / «Рискованнее»
2. **Матчмейкинг**: `/auto-match` → задать количество мест, цену входа, призовой фонд, формат игры → «Найти комнату» → результаты с прогнозом выигрыша
3. **Ручной выбор**: `/games` → фильтры по цене и формату, сортировка → «Играть» в любой комнате
4. **Бот победил**: комната «Быстрая» — победитель бот; его часть фонда остаётся в системе, видно на экране победителей и в системном фонде
5. **Нехватка баллов**: много раз проиграйте в «Быстрой» (вход 50) — кнопки входа/буста заблокируются с причиной и предложением подобрать комнату
6. **Администрирование**: `/admin` → изменить параметры комнаты и тип оболочки → «Проверить» → живые предупреждения → `/economy`
7. **Прозрачность**: `/log` — журнал раундов с ID, seed и победителем (новыми строками пополняется после сыгранных раундов)

## Статус

Готов UI-прототип фронтенда (все экраны пользовательского и административного пути, три игровые оболочки, живая экономика на клиенте). Следующие шаги по кейсу: backend с RNG и расчётом весов (рекомендуется Java), real-time обновления состояния комнаты (WebSocket/SSE), резервирование бонусных баллов на стороне сервера, хранение состояния (рекомендуется PostgreSQL). Клиентская логика результата (штрих `data.ts → getRoundResult`) позже заменяется на вызов backend-endpoint без изменения экранов.
